# Миграция направлений платежей и кейсов

## Цель

Перенести legacy-данные ACF блоков «Услуги» и «Кейсы» в действующий конструктор секций без потери привязки к страницам, не перезаписывая уже заполненные локальные данные конструктора.

## Схема ACF и вывод

- В `Направления платежей → Главная → Элементы` добавляется текстовое поле `price` с меткой «Цена».
- Цена выводится внутри `<h3 class="shipment-card__title">` отдельным элементом `.shipment-card__price`; пустая цена не создаёт разметку.
- В строки конструктора `shipments` и `cases` добавляется select `description_mode`: `inherit` («Наследовать») и `hide` («Скрыть»), по умолчанию `inherit`.
- При `hide` пустое локальное описание не наследует сквозное. Непустое локальное описание продолжает выводиться.

## Главная страница

- Источник: страница 24, `uslugi_service` из группы «Блоки → Услуги».
- Назначение: сквозной `shipments.main.items`, а не локальный override страницы.
- Карточки сопоставляются по позиции. Переносятся `zagolovok → title`, `tekst → text`, `czena → price`, `ssylka → link`.
- Существующие сквозные `image` и `tags` сохраняются.
- Заголовок и описание самой секции не меняются.
- Legacy-кейсы страницы 24 становятся сквозным `cases`: `zagolovok_reev → title`; `klienty_rev` становится `items`.
- Сквозные описания `shipments` и `cases` на главной сохраняются.

## Внутренние страницы

- `zagolovok_services` и `uslugi_services` мигрируются только у страниц, использующих стандартный `page.php` (пустой/default template slug).
- `zagolovok_services → shipments.title`.
- Карточки: `zagolovok → title`, `tekst → text`, `izobrazhenie_services → image`; `cardclass` пропускается.
- Локальные `tags` и `link` остаются пустыми. `description_mode` устанавливается в `hide`.
- Кейсы мигрируются у всех страниц со статусами `publish`, `future`, `draft`, `pending`, `private`, независимо от шаблона.
- Карточки кейсов: `zagolovok → text`, `imya → title`, `kompaniya → caption`, `izobrazheie → image`, `value = ★★★★★`.
- `izobrazheniya_reev` и `colors` пропускаются. Локальные ссылки остаются пустыми. `description_mode = hide`.
- Если собственных `klienty_rev` нет, но заполнен заголовок кейсов, строка наследует сквозные карточки главной.
- Старые true/false-переключатели не мигрируются: заполненный контент создаёт включённую секцию, пустой — не создаёт секцию.

## Порядок

На мигрируемых страницах начало конструктора нормализуется до `hero → shipments → cases`; остальные существующие строки сохраняют относительный порядок. Если hero отсутствует, `shipments` и `cases` становятся первыми. Существующие строки этих типов переиспользуются, а не дублируются.

## Конфликты и безопасность

- Непустые overrides существующих `shipments`/`cases` не перезаписываются. Dry-run перечисляет конфликт и оставляет значение редактора.
- Пустые строки дополняются, отсутствующие — создаются.
- Команда по умолчанию выполняет dry-run. `--apply` пишет данные, повторно читает и проверяет каждую запись, затем ставит version marker.
- После marker старые поля скрываются из интерфейса ACF через `acf/prepare_field`; raw `postmeta` не удаляется и остаётся доступным для отката.
- SEO-ветка страницы 2054 не меняется.
- Перед `--apply` пользователь получает полный отчёт и отдельно подтверждает запись в локальную базу Studio.

## Проверка

- PHPUnit покрывает чистые преобразования, порядок, наследование, конфликты и идемпотентность.
- Интеграционные WP-CLI проверки подтверждают ACF-схему, режим описания, разметку цены и отсутствие регрессий секций.
- Dry-run выполняется на локальной Studio-базе; apply в рамках текущего этапа не выполняется без отдельного подтверждения.
