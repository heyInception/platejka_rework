# Редактирование контента и файлов `platejka_rework`

Инструкция относится к локальному тестовому сайту и теме
`wp-content/themes/platejka_rework`. Она не является инструкцией по публикации
на production.

## 1. Что редактировать в WordPress, а что в файлах

Используйте админ-панель WordPress для текстов, изображений, ссылок, меню,
контактов и форм, если для них уже существует поле ACF или настройка WordPress.
Такие изменения сохраняются в базе данных и не требуют правки PHP/HTML/CSS.

Редактируйте файлы темы только в следующих случаях:

- нужно изменить разметку или дизайн секции;
- нужно исправить CSS или JavaScript;
- у секции пока нет ACF-полей и её текст всё ещё берётся из перенесённого HTML;
- нужно добавить новую секцию или новый редактируемый слот.

Не редактируйте исходник дизайна в
`C:\project\platejka-new\wordpress`. Рабочая копия дизайна уже перенесена в
тему. Также не следует править файлы ядра WordPress, `vendor`, сторонние
плагины или сгенерированные файлы кэша.

## 2. Редактирование страниц в админ-панели

1. Откройте **Страницы → Все страницы**.
2. Выберите нужную страницу:
   - **Главная** — ID `24`, slug `glavnaya`;
   - **Платежи в Китай** — ID `1873`, slug `china`;
   - **О компании** — ID `22`, slug `o-kompanii`.
3. Измените нужные поля ACF под редактором страницы.
4. Нажмите **Обновить**.
5. Откройте страницу на сайте и проверьте изменённый блок.

Порядок блоков в шаблонах заблокирован. Не пытайтесь переставлять или удалять
их через редактор блоков: состав страниц задаётся файлами шаблонов темы.

### Главная

Группа ACF **«Главная — новые секции»** позволяет редактировать:

- показ блока отзывов;
- надзаголовок, заголовок и описание отзывов;
- показ формы заявки;
- заголовок формы заявки.

Остальные уже существовавшие поля главной продолжают работать под прежними
названиями: первый экран, услуги, этапы работы, калькулятор, преимущества,
направления, кейсы/отзывы и FAQ. Их точное соответствие новым секциям приведено
в [карте секций](./section-map.md).

### Платежи в Китай

Группа ACF **«Платежи в Китай — форма заявки»** позволяет:

- показать или скрыть форму;
- изменить заголовок формы.

Первый экран и FAQ используют существующие поля ACF. SEO-блок использует
заголовок и основной текст самой страницы. Остальные секции, помеченные в
карте как `design_html`, пока берут текст из перенесённых HTML-шаблонов.

### О компании

Группа ACF **«О компании — секции нового дизайна»** содержит поля для:

- первого экрана: надзаголовок, заголовок, описание и фон;
- офиса: заголовок, описание и карта;
- отзывов: надзаголовок, заголовок и описание;
- инфраструктуры: заголовок и карта;
- финансового блока: заголовок, описание, ссылка и изображение;
- сотрудников: заголовок, цитата, имя, должность, фото сотрудника и команды;
- выставок: заголовок, описание и изображение;
- истории развития: заголовок;
- формы и контактных карточек: тексты и ссылки Telegram, WhatsApp, VK,
  VC.ru, РБК и Лента.ру.

Пустая ссылка в финансовом или социальном блоке не создаёт фиктивную ссылку
`#`: элемент будет скрыт или показан без активной ссылки.

### Значения по умолчанию

Новые ACF-поля используют текст из перенесённого дизайна как значение по
умолчанию. Пока страницу не сохраняли, этот текст может отображаться без
отдельной записи в базе. После сохранения введённое значение становится
приоритетным.

Если нужно вернуть конкретное поле к тексту дизайна, скопируйте нужный текст
из `assets/src/sections/<секция>/template.html` в поле ACF. Простое очищение
поля не всегда означает возврат к default: поведение зависит от конкретного
поля и наличия сохранённого meta-значения.

## 3. Какие секции пока редактируются только в файлах

В [карте секций](./section-map.md) смотрите колонку **«Источник»**:

- `legacy_acf` — редактировать в существующих полях ACF;
- `legacy_post` — редактировать заголовок/текст страницы;
- `local_acf` или `design_html + local ACF override` — редактировать в новых
  полях ACF;
- `design_html` — текст пока находится в HTML темы;
- `legacy_template` — статический текст перенесён из старого шаблона.

Для `design_html` основной файл текста:

```text
themes/platejka_rework/assets/src/sections/<slug-секции>/template.html
```

Например:

```text
themes/platejka_rework/assets/src/sections/documents/template.html
themes/platejka_rework/assets/src/sections/protection/template.html
```

Правьте только текстовые узлы, не меняя классы, `data-*` атрибуты, структуру
слайдеров и пути к изображениям без необходимости. Эти элементы используются
CSS, JavaScript и PHP-адаптером.

Если статический текст должен регулярно меняться редактором, правильное
решение — добавить ему поле ACF и подставлять значение в PHP, а не продолжать
редактировать HTML вручную.

## 4. Меню, шапка, подвал и контакты

### Меню

Откройте **Внешний вид → Меню** и редактируйте назначения:

- `Основная навигация` (`menu-1`);
- `Мобильная навигация` (`menu-2`).

Сохраняйте иерархию родительских и дочерних пунктов. Шапка сама строит
подменю из этой структуры.

### Контакты и подвал

Контактные данные берутся со страницы настроек ACF **«Контакты»**. Там
редактируются адрес, часы работы, почта, телефон, реквизиты компании,
социальные сети и группы ссылок подвала.

Логотип меняется через стандартную настройку WordPress **Логотип сайта**.

Файлы представления общих элементов:

```text
themes/platejka_rework/blocks/site-header/render.php
themes/platejka_rework/blocks/site-footer/render.php
themes/platejka_rework/assets/src/css/components/header.css
themes/platejka_rework/assets/src/css/components/footer.css
themes/platejka_rework/assets/src/js/components/header.js
```

## 5. Формы и калькулятор

Формы редактируются в **Контакты → Контактные формы**. Тема использует
фиксированные ID существующих Contact Form 7:

| Назначение | ID |
| --- | ---: |
| Обычная заявка | `305` |
| Страница «О компании» | `3321` |
| Форма в шапке | `3542` |
| Перевод/калькулятор | `4966` |

Не удаляйте эти формы и не создавайте вместо них новые без обновления карты
ID в `themes/platejka_rework/inc/global-blocks.php`. При изменении полей CF7
проверьте передачу заявки в amoCRM: сторонняя интеграция может ожидать точные
имена полей.

Калькулятор отправляет запрос в REST endpoint
`/wp-json/platejka/v1/calculation`. Его расчётная логика и курсы находятся в
`wp-content/plugins/platejka-core`; внешний вид — в блоке `calculator` темы.
Не переносите бизнес-логику расчёта в JavaScript.

Основные файлы:

```text
themes/platejka_rework/blocks/calculator/render.php
themes/platejka_rework/blocks/call/render.php
themes/platejka_rework/assets/src/css/components/calculator.css
themes/platejka_rework/assets/src/css/components/forms.css
themes/platejka_rework/assets/src/js/components/calculator.js
plugins/platejka-core/
```

## 6. Структура файлов одной секции

Каждая секция обычно состоит из четырёх частей:

```text
themes/platejka_rework/
├── blocks/<section>/block.json       регистрация блока
├── blocks/<section>/render.php       серверный вывод блока
└── assets/src/sections/<section>/
    ├── template.html                 перенесённая HTML-разметка
    ├── style.css                     стили секции
    ├── script.js                     логика секции, если нужна
    └── img/                          изображения секции
```

Связующие файлы:

- `inc/page-sections.php` — регистрация секций, новые группы ACF и подстановка
  ACF-значений в перенесённую разметку;
- `inc/content-map.php` — карта источников данных и правила видимости;
- `inc/global-blocks.php` — шапка, подвал, формы, калькулятор, меню и контакты;
- `inc/assets.php` — регистрация и подключение CSS/JS;
- `templates/front-page.html` — порядок блоков главной;
- `templates/page-china.html` — порядок блоков «Платежи в Китай»;
- `templates/page-o-kompanii.html` — порядок блоков «О компании».

## 7. Как изменить дизайн существующей секции

1. Найдите slug секции в [карте секций](./section-map.md).
2. Измените её `template.html`, `style.css` или `script.js` внутри
   `assets/src/sections/<slug>/`.
3. Если меняется класс или структура элемента, проверьте селекторы этой секции
   в `inc/page-sections.php`: PHP может искать конкретный CSS-класс, чтобы
   заменить текст или изображение значением ACF.
4. Не заменяйте экспортированный блок самодельной упрощённой разметкой. Новые
   правки следует вносить поверх перенесённого и уже проверенного дизайна.
5. Проверьте все страницы, на которых используется этот slug: некоторые
   секции общие для главной и страницы Китая.

## 8. Как добавить новую секцию

1. Скопируйте точные HTML, CSS, JS и изображения секции из утверждённого
   экспорта в `assets/src/sections/<новый-slug>/`.
2. Создайте `blocks/<новый-slug>/block.json` и `render.php` по образцу близкой
   динамической секции.
3. Зарегистрируйте ассеты и разрешённые страницы в `inc/page-sections.php`.
4. Добавьте источник данных и правила видимости в `inc/content-map.php`.
5. Если текст должен редактироваться, добавьте стабильные поля ACF и безопасную
   подстановку. Текст, URL и атрибуты должны проходить WordPress escaping.
6. Вставьте блок в нужный файл `templates/*.html` на правильную позицию.
7. Добавьте или обновите соответствующую проверку в `tests/theme/`.
8. Обновите [карту секций](./section-map.md).

Не переименовывайте существующие legacy meta names и field keys: заполненный
контент старой темы зависит от них.

## 9. Минимальная проверка после изменений

Сначала проверьте изменённую страницу вручную в локальном WordPress. Затем
запустите только относящиеся к изменению проверки из корня сайта
`C:\Users\Inception\Studio\platejka`:

```powershell
studio wp --path C:\Users\Inception\Studio\platejka eval-file C:\Users\Inception\Studio\platejka\wp-content\tests\theme\global-navigation.php
studio wp --path C:\Users\Inception\Studio\platejka eval-file C:\Users\Inception\Studio\platejka\wp-content\tests\theme\forms-calculator.php
studio wp --path C:\Users\Inception\Studio\platejka eval-file C:\Users\Inception\Studio\platejka\wp-content\tests\theme\content-map.php
studio wp --path C:\Users\Inception\Studio\platejka eval-file C:\Users\Inception\Studio\platejka\wp-content\tests\theme\home-page.php
studio wp --path C:\Users\Inception\Studio\platejka eval-file C:\Users\Inception\Studio\platejka\wp-content\tests\theme\china-page.php
studio wp --path C:\Users\Inception\Studio\platejka eval-file C:\Users\Inception\Studio\platejka\wp-content\tests\theme\about-page.php
studio wp --path C:\Users\Inception\Studio\platejka eval-file C:\Users\Inception\Studio\platejka\wp-content\tests\smoke\plugin-bootstrap.php
```

Запускать все команды после каждой мелкой правки не нужно:

- шапка/подвал/меню — `global-navigation.php`;
- форма/калькулятор — `forms-calculator.php` и `plugin-bootstrap.php`;
- карта ACF — `content-map.php`;
- конкретная страница — соответствующий `home-page.php`, `china-page.php` или
  `about-page.php`.

Ориентируйтесь на итоговую строку теста и значение `0 failures`. В текущем
быстром режиме автоматические адаптивные, Lighthouse и кроссбраузерные
проверки не требуются; адаптивы проверяются владельцем вручную.

Если после очистки кэша схема CF7 возвращает `404`, можно восстановить только
сгенерированный локальный кэш существующей функцией:

```powershell
studio wp --path C:\Users\Inception\Studio\platejka eval "var_export( platejka_cf7_schema_cache_warm_all() );"
```

WebP Express и Easy FancyBox сейчас отключены, WP Meteor удалён. Не добавляйте
в тему обходы для этих плагинов без отдельного решения об их возврате.

## 10. Безопасный порядок работы

1. Перед изменениями выполните `git status --short`.
2. Меняйте одну секцию или одну связанную задачу за раз.
3. Проверьте `git diff` и убедитесь, что не затронуты чужие или несвязанные
   файлы.
4. Выполните минимальный профиль проверки из раздела выше.
5. Сделайте отдельный коммит с понятным сообщением.
6. Не используйте `git reset --hard` для отката пользовательских изменений.
7. Не отправляйте тему на production без отдельного бэкапа, проверки реальной
   доставки CF7/amoCRM и согласованного плана публикации.
